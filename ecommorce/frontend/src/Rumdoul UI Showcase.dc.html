01 · Overview

The brief, and what I shipped

Take a loud, playful food-delivery layout as reference and rebuild it as a coffee shop storefront — but make the motion do real work: cards that stack like a deck and fan out under the scrollbar, a ribbon that draws itself down the page, and an ordering path that never leaves the page.

The problem

Reference layouts like this look great in a static mock and fall apart in build: the fun is all in the scroll, and the scroll is where accessibility and performance usually break.

The approach

Build the correct static layout first, then let GSAP take it apart. Every animated section renders complete with zero animation frames — motion is strictly additive.

Scope

• Sticky header, cart counter, mobile nav • Hero with floating product frames • Four category entry cards • Pinned deck-to-fan spotlight cards • Scroll-drawn zigzag ribbon & spine • Filterable 12-item menu grid • Product modal with size pricing • Cart drawer with live totals • Three-step checkout & payment • Subscription, reviews, store locator

03 · Signature interaction

Deck to fan, on scroll

Step 1

Four cards render in a plain CSS grid. That is the layout the page has with JavaScript disabled.

Step 2

GSAP measures every cell, freezes the cards absolutely at those coordinates, and pins the section.

Step 3

A scrubbed from() timeline pulls them back into a squared-up deck. Scrolling plays it forward.

Re-measure

A refreshInit hook re-runs the measurement on resize, so the fan never drifts.

☛

All four cards share one type ramp and one ink colour — only the ground changes. Each card carries a single hero drink or food item, and hovering slides up an ink bar reading “Click to order · pay in 2 taps”.

04 · Catalogue

Menu & filtering

Twelve items across four categories. The sidebar holds the filter, the reassurance list and a “surprise me” shortcut that drops four bestsellers straight into the bag.

Sidebar that folds

Flexbox holy-grail sizing — the filter sits beside the grid on desktop and becomes a bar above it when the grid runs out of room. No media query.

Card hover

Lift, tilt, photo zoom to 1.10, and the order cue slides over the image — one paused GSAP timeline per card, reversed on leave.

Two targets, one card

The card opens the detail modal; the Add button stops propagation and drops straight into the bag.

05 · Order flow

From hover to paid

Four states, no page loads: hover cue → product detail with size pricing → cart drawer with live totals and a free-delivery threshold → three-step checkout ending in a confirmed order number.

Product detail

Size changes the price live (−$0.50 / base / +$0.80). Two exits: add and pay, or just add.

Payment step

Local rails first — ABA Pay and Wing alongside card, which is what people in Phnom Penh actually use.

Live totals

Subtotal, delivery and total recompute on every quantity change. Delivery flips to free at $12 — the threshold is a component prop, not a magic number.

Shared photo slots

Drawer thumbnails key off the same slot id as the menu card, so one uploaded photo shows everywhere the item appears.

Empty state

“Nothing brewing yet” with a route back to the menu — written in the brand voice, not the framework’s.

07 · Build

Tech stack & my role

Stack

React — one component per UI element, props-driven, no global store needed at this size. GSAP + ScrollTrigger — pinning, scrubbing, matchMedia breakpoints, context-scoped cleanup. Tailwind CSS — breakpoint utilities layered over an inline-style base so first paint never waits on a stylesheet. SVG — ribbon paths, text-on-path, dash-offset drawing, the flower mark.

My role

End to end: brand direction, colour and type system, wireframes, high-fidelity UI, motion design, and the front-end build. Copywriting for every screen is mine too.

Engineering decisions worth naming

01

Motion never gates content. Every scroll tween uses immediateRender: false, so a backgrounded tab, a reduced-motion setting or a print render still shows a complete page.

02

Scoped teardown. Each component owns a gsap.context() and reverts only its own tweens, so a hot reload in one card can’t kill the ScrollTriggers of another.

03

Intrinsic responsiveness. Layout is auto-fit/minmax(), clamp() and flex-wrap; breakpoints only handle what CSS can’t infer, like hiding the desktop nav.

04

Pure state updates. Cart quantities are updated immutably, which is what keeps the counter honest under React’s double-invoked updaters in development.
